# Interface Control: Communication and Message Model

| Document ID | MPS-ICD-COMM-001 |
|---|---|
| Version | 1.1 |
| Status | BASELINED |

## Message classes
- **Event**: immutable fact observed/generated by a component.
- **Command**: requested action with authorization/idempotency requirements.
- **Telemetry**: operational measurement; may be aggregated/dropped by retention policy.
- **Configuration**: versioned desired state.

## Event minimum fields
`schema_version, event_id, source, source_sequence, event_type, occurred_at, priority`

Authenticated transports/envelopes add `nonce/issued_at/key-id/MAC-or-signature` as applicable.

## Priority
- P0: critical intrusion/security event; preserve preferentially.
- P1: high fault/tamper/security state.
- P2: normal state change.
- P3: telemetry.
- P4: debug/verbose diagnostics.

## Delivery semantics
Transport is **at-least-once**; consumers are idempotent. A node/gateway may remove a queued event only after a `DURABLE_LOCAL` or stronger acknowledgement.

ACK progression:
`RECEIVED_LOCAL → DURABLE_LOCAL → DELIVERED_EXTERNAL → PROCESSED_EXTERNAL`

A byte-level send/receive success is not a durable ACK.

## Sequence handling
Per-source monotonically increasing sequence numbers support duplicate/stale/gap detection. Missing sequences are diagnostic/retransmission signals; they must not change original event timestamps.

## Offline recovery
When Internet/upstream is unavailable, gateway persists eligible events and continues local processing. After recovery: verify connectivity/authentication, send P0/P1 first, throttle backlog replay, deduplicate, then synchronize lower-priority data.
